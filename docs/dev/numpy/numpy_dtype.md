配列の型と型の間の変換
=========================================

NumPyはPythonよりもはるかに多くの種類の数値型をサポートしている。
このセクションでは、利用可能な型と、配列のデータ型を変更する方法を示す。

NumPyの数値型は `numpy.dtype`(データ型)オブジェクトのインスタンスであり、
それぞれが固有の特性を持つ。``import numpy as np`` でNumPyをインポートすれば、
numpyのトップレベルAPIにあるスカラー型(例: `numpy.bool`、`numpy.float32` など)
を使って、指定したdtypeで配列を作成できる。

これらのスカラー型は、多くのnumpy関数やメソッドが受け付ける dtype キーワード
引数として渡すことができる。例えば::

      >>> z = np.arange(3, dtype=np.uint8)
      >>> z
      array([0, 1, 2], dtype=uint8)

配列の型は文字コードで指定することもできる。例えば::

    >>> np.array([1, 2, 3], dtype='f')
    array([1.,  2.,  3.], dtype=float32)
    >>> np.array([1, 2, 3], dtype='d')
    array([1.,  2.,  3.], dtype=float64)

バイトオーダーなどのパラメータの指定方法を含む、データ型オブジェクトの
指定・構築に関する詳細は :ref:`arrays.dtypes.constructing` を参照。

配列の型を調べるには、dtype属性を確認する::

      >>> z.dtype
      dtype('uint8')

dtypeオブジェクトには、そのビット幅やバイトオーダーなど、型に関する情報も
含まれている。データ型は、それが整数であるかどうかといった型のプロパティを
間接的に調べるためにも使用できる::

    >>> d = np.dtype(np.int64)
    >>> d
    dtype('int64')

    >>> np.issubdtype(d, np.integer)
    True

    >>> np.issubdtype(d, np.floating)
    False

配列の型を変換するには、.astype() メソッドを使用する。例えば

    >>> z.astype(np.float64)                 #doctest: +NORMALIZE_WHITESPACE
    array([0.,  1.,  2.])

上記の例では、`numpy.float64` の代わりに *Python* の float オブジェクトを
dtypeとして使うこともできた点に注意。NumPyは
:class:`int` が `numpy.int_` を指すこと、:class:`bool` が
`numpy.bool` を意味すること、:class:`float` が `numpy.float64` であること、
:class:`complex` が `numpy.complex128` であることを認識している。それ以外の
データ型にはPythonの対応する型は存在しない。

変換が値を超えてオーバーフローすることがある。例えば `numpy.int64` の値300を
`numpy.int8` に変換する場合である。NumPyはCのキャストルールに従うため、
この値はオーバーフローして44 ``(300 - 256)`` になる。このようなオーバーフローを
避けたい場合は、``casting`` 引数に ``same_value`` を指定することで、
オーバーフロー動作を失敗させることができる(:ref:`overflow-errors` も参照)::

    >>> z.astype(np.float64, casting="same_value")   #doctest: +NORMALIZE_WHITESPACE
    array([0.,  1.,  2.])


数値データ型
--------------------

真偽値(``bool``)、整数(``int``)、符号なし整数(``uint``)、浮動小数点数
(``float``)、複素数(``complex``)を表す5つの基本数値型がある。基本数値型の
名前とビットサイズを組み合わせることで、具体的な型が定義される。ビットサイズ
とは、メモリ上で1つの値を表現するために必要なビット数のことである。例えば
`numpy.float64` は64ビットの浮動小数点データ型である。`numpy.int_` や
`numpy.intp` のような一部の型は、プラットフォーム(例えば32ビットCPUと
64ビットCPUのアーキテクチャの違い)によって異なるビットサイズを持つ。
これは、生のメモリを直接扱う低レベルコード(CやFortranなど)とやり取りする際に
考慮すべき点である。

文字列とバイト列のデータ型
--------------------------------

数値型に加えて、NumPyはUnicode文字列を `numpy.str_` dtype(文字コード ``U``)、
null終端されたバイト列を `numpy.bytes_`(文字コード ``S``)、任意のバイト列を
`numpy.void`(文字コード ``V``)を通じて格納することもサポートしている。

上記はすべて *固定幅(fixed-width)* のデータ型である。これらは、配列内の
1つのデータ要素が収まる必要のある幅(バイト数またはUnicodeコードポイント数)を
パラメータとして持つ。これは、このdtypeを使ってバイト列や文字列の配列を
格納するには、事前に最も長いテキストまたはバイト列のサイズを知っているか
計算しておく必要があることを意味する。

例として、``"hello"`` と ``"world!"`` という単語を格納する配列を作成できる::

    >>> np.array(["hello", "world!"])
    array(['hello', 'world!'], dtype='<U6')

ここでは、データ型は最大6コードポイントのUnicode文字列として検出されており、
両方のエントリを切り詰めずに格納するのに十分な長さである。より短い、または
より長いデータ型を指定した場合、文字列は指定した幅に収まるように切り詰め
られるか、ゼロ埋めされる::

    >>> np.array(["hello", "world!"], dtype="U5")
    array(['hello', 'world'], dtype='<U5')
    >>> np.array(["hello", "world!"], dtype="U7")
    array(['hello', 'world!'], dtype='<U7')

bytesデータ型を使い、配列バッファ内のバイトをNumPyに出力させることで、
ゼロ埋めの様子をもう少しはっきりと確認できる::

    >>> np.array(["hello", "world"], dtype="S7").tobytes()
    b'hello\x00\x00world\x00\x00'

各エントリには2バイトの余分なnullバイトが埋め込まれている。ただし、NumPyは
意図的に格納された末尾のnullと、パディング用のnullを区別できないことに
注意すること::

    >>> x = [b"hello\0\0", b"world"]
    >>> a = np.array(x, dtype="S7")
    >>> print(a[0])
    b"hello"
    >>> a[0] == x[0]
    False

末尾のnullバイトを保持し、そのまま復元(round-trip)できるようにする必要が
ある場合は、非構造化のvoidデータ型を使う必要がある::

    >>> a = np.array(x, dtype="V7")
    >>> a
    array([b'\x68\x65\x6C\x6C\x6F\x00\x00', b'\x77\x6F\x72\x6C\x64\x00\x00'],
        dtype='|V7')
    >>> a[0] == np.void(x[0])
    True

上記に挙げていない発展的な型については
:ref:`structured_arrays` のセクションで解説する。

NumPyのデータ型とCのデータ型の対応関係
======================================================

NumPyは、ビットサイズに基づく型名と、C言語の型名に基づく型名の両方を提供する。
C言語の型の定義はプラットフォーム依存であるため、NumPyを使用するプログラムで
プラットフォーム依存の挙動を避けるには、明示的にビットサイズを示した型名を
優先的に使用するべきである。

プラットフォーム依存のC言語の型を参照する方が自然な場面でCコードとの連携を
容易にするため、NumPyはそのプラットフォームにおけるC言語の型に対応する型
エイリアスも提供している。一部のdtypeには、`numpy.bool_` のように、組み込みの
Python型名との混同を避けるために末尾にアンダースコアが付いている。

| Canonical Python API name                  | Python API "C-like" name | Actual C type                       | 概要                                                                                            |
| ------------------------------------------ | ------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| `numpy.bool` or `numpy.bool_`              | N/A                      | ``bool`` (defined in ``stdbool.h``) | 1バイトとして格納される真偽値(TrueまたはFalse)                                                  |
| `numpy.int8`                               | `numpy.byte`             | ``signed char``                     | 8ビットのプラットフォーム定義整数                                                               |
| `numpy.uint8`                              | `numpy.ubyte`            | ``unsigned char``                   | 8ビットの符号なしプラットフォーム定義整数型。                                                   |
| `numpy.int16`                              | `numpy.short`            | ``short``                           | 16ビットのプラットフォーム定義整数型。                                                          |
| `numpy.uint16`                             | `numpy.ushort`           | ``unsigned short``                  | 16ビットの符号なしプラットフォーム定義整数型。                                                  |
| `numpy.int32`                              | `numpy.intc`             | ``int``                             | 32ビットのプラットフォーム定義整数型。                                                          |
| `numpy.uint32`                             | `numpy.uintc`            | ``unsigned int``                    | 32ビットの符号なしプラットフォーム定義整数型                                                    |

一式が用意されている(:ref:`sized-aliases` を参照)。

配列スカラー
=============

NumPyは一般に、配列の要素を配列スカラー(dtypeを持つスカラー)として返す。
配列スカラーはPythonのスカラーとは異なるが、ほとんどの場合は相互に置き換えて
使用できる(主な例外は、v2.x以前の古いバージョンのPythonで、整数の配列
スカラーがリストやタプルのインデックスとして使えない場合である)。コードが
スカラーの非常に特定の属性を要求する場合や、値がPythonのスカラーであるかを
明示的にチェックする場合など、例外もいくつか存在する。一般に、こうした問題は、
対応するPythonの型関数(例: :class:`int`、:class:`float`、:class:`complex`、
:class:`str`)を使って配列スカラーをPythonのスカラーに明示的に変換することで
簡単に解決できる。

配列スカラーを使う主な利点は、配列の型を保持できる点である(Pythonには
``int16`` のような対応するスカラー型が存在しない場合がある)。したがって、
配列スカラーを使うことで、値が配列の中にあるかどうかにかかわらず、配列と
スカラーとで同一の挙動が保証される。NumPyのスカラーは、配列が持つ多くの
メソッドと同じメソッドも持っている。

オーバーフローエラー
===============

NumPyの数値型は固定サイズであるため、値がそのデータ型で利用可能な容量よりも
多くのメモリを必要とする場合、オーバーフローエラーが発生することがある。
例えば、`numpy.power` は64ビット整数に対しては ``100 ** 9`` を正しく
計算するが、32ビット整数に対しては -1486618624(誤った値)を返す。

    >>> np.power(100, 9, dtype=np.int64)
    1000000000000000000
    >>> np.power(100, 9, dtype=np.int32)
    np.int32(-1486618624)

整数のオーバーフローに関して、NumPyとPythonの整数型の挙動は大きく異なり、
NumPyの整数がPythonの :class:`int` と同じように振る舞うことを期待する
ユーザーを混乱させることがある。NumPyとは異なり、Pythonの :class:`int` の
サイズは可変である。これは、Pythonの整数はどんな整数でも収まるように
拡張され、オーバーフローしないことを意味する。

NumPyは、NumPyの整数型・浮動小数点型それぞれの最小値・最大値を確認するために
`numpy.iinfo` と `numpy.finfo` を提供している::

    >>> np.iinfo(int) # このシステムでのデフォルト整数の範囲
    iinfo(min=-9223372036854775808, max=9223372036854775807, dtype=int64)
    >>> np.iinfo(np.int32) # 32ビット整数の範囲
    iinfo(min=-2147483648, max=2147483647, dtype=int32)
    >>> np.iinfo(np.int64) # 64ビット整数の範囲
    iinfo(min=-9223372036854775808, max=9223372036854775807, dtype=int64)

64ビット整数でもまだ小さすぎる場合、結果は浮動小数点数にキャストされることが
ある。浮動小数点数は、より広いが厳密ではない値の範囲を提供する。

    >>> np.power(100, 100, dtype=np.int64) # 64ビット整数でも誤った結果になる
    0
    >>> np.power(100, 100, dtype=np.float64)
    1e+200

浮動小数点数の精度
========================

NumPyの多くの関数、特に `numpy.linalg` にある関数は浮動小数点演算を伴い、
コンピュータが10進数を表現する方法に起因して、わずかな不正確さが生じることが
ある。例えば、浮動小数点数を含む基本的な算術演算を行う場合:

    >>> 0.3 - 0.2 - 0.1  # 浮動小数点の精度により、これは0にならない
    -2.7755575615628914e-17

このようなケースに対応するには、厳密な等価性をチェックするのではなく、
`np.isclose` のような関数を使って値を比較することが推奨される:

    >>> np.isclose(0.3 - 0.2 - 0.1, 0, rtol=1e-05)  # 0に近いかどうかをチェック
    True

この例では、`np.isclose` は相対許容誤差(relative tolerance)を適用することで、
浮動小数点計算で生じるわずかな不正確さを考慮し、小さな閾値内にある結果を
「近い」とみなしている。

計算における精度についての詳細は
`浮動小数点演算 <https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html>`_
を参照。


拡張精度
==================

Pythonの浮動小数点数は通常64ビットの浮動小数点数であり、`numpy.float64` と
ほぼ同等である。特殊な状況では、より高い精度の浮動小数点数を使うことが
有用な場合がある。これがnumpyで可能かどうかは、ハードウェアと開発環境に
依存する。具体的には、x86マシンは80ビット精度のハードウェア浮動小数点を
提供しており、ほとんどのCコンパイラはこれを ``long double`` 型として
提供しているが、MSVC(Windowsビルドの標準)は ``long double`` を
``double``(64ビット)と同一のものにしている。NumPyは、コンパイラの
``long double`` を `numpy.longdouble`(複素数の場合は ``np.clongdouble``)
として利用可能にしている。自分の環境のnumpyが何を提供しているかは
``np.finfo(np.longdouble)`` で確認できる。

NumPyは、Cの ``long double`` より高精度なdtypeは提供していない。特に、
128ビットのIEEE quad precisionデータ型(FORTRANの ``REAL*16``)は
利用できない。

効率的なメモリアラインメントのため、`numpy.longdouble` は通常、96ビット
または128ビットにゼロビットでパディングされて格納される。どちらがより
効率的かはハードウェアと開発環境に依存する。一般的に32ビットシステムでは
96ビットにパディングされ、64ビットシステムでは128ビットにパディングされる。
``np.longdouble`` はシステムのデフォルトにパディングされる。``np.float96``
と ``np.float128`` は、特定のパディングを望むユーザー向けに提供されている。
名前とは裏腹に、``np.float96`` と ``np.float128`` が提供する精度は
``np.longdouble`` と同じ、すなわちほとんどのx86マシンでは80ビット、
標準的なWindowsビルドでは64ビットに過ぎない。

`numpy.longdouble` がPythonの :class:`float` よりも高い精度を提供する
場合であっても、その余分な精度は容易に失われてしまうことに注意すること。
Pythonはしばしば値を ``float`` を経由させるよう強制するためである。例えば、
``%`` フォーマット演算子はその引数を標準的なPythonの型に変換することを
要求するため、たとえ多くの小数点以下桁数を要求したとしても、拡張精度を
保持することは不可能である。コードをテストする際には
``1 + np.finfo(np.longdouble).eps`` という値を使うと有用な場合がある。
