# PEP 8 命名規則ガイドライン

本書は、Pythonの公式コーディング規約「PEP 8」に準拠した命名規則（Naming Conventions）についてまとめたドキュメントである。コードの可読性、保守性、およびチーム開発における一貫性を担保するため、以下の規則を厳守すること。

---

## 1. 命名規則一覧

対象となる要素に応じ、適用すべきスタイル、注意点、および具体的なコード例を以下に示す。


| 対象要素                               | 推奨スタイル                                         | 特殊ルール注意点                                                                                                                             | 具体的なコード例                                                                           |
| :------------------------------------- | :--------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **パッケージ名**<br>（ディレクトリ名） | **すべて小文字**<br>（短く簡潔に）                   | アンダースコア（ `_` ）は原則として**使用しない**（非推奨）。<br>インポート文における記述の容易性を最優先する。                              | `models`<br>`utils`<br>`analytics`                                                         |
| **モジュール名**<br>（ファイル名）     | **すべて小文字**<br>（スネークケース）               | 可読性を向上させる目的に限り、アンダースコア（ `_` ）の使用を許容する。                                                                      | `db.py`<br>`json_parser.py`<br>`auth_service.py`                                           |
| **クラス名**                           | **頭文字を大文字**<br>（パスカルケース）             | 単語の区切りにアンダースコアは使用しない。<br>`HTTP` や `API` などの略語も、先頭のみを大文字表記とする。                                     | `User`<br>`HttpClient`<br>`DatabaseConnection`                                             |
| **変数型**<br>（型変数型エイリアス）   | **頭文字を大文字**<br>（パスカルケース）             | 単一の大文字（ `T` など）や短い名称が好まれる。<br>Pythonの標準組み込み型（ `int`, `str` など）はすべて小文字とする。                        | `T`（型変数）<br>`UserId = int`<br>`Coordinate = tuple[float, float]`                      |
| **例外名**<br>（エラークラス）         | **頭文字を大文字**<br>（パスカルケース）             | **末尾には必ず `Error` を付与する**。<br>独自の例外グループを定義する際の基底クラスは `Exception` も可とする。                               | `ValidationError`<br>`NetworkTimeoutError`<br>`MyProjectException`（基底）                 |
| **関数名**                             | **すべて小文字**<br>（スネークケース）               | **動詞から開始する**ことで可読性を高める（ `get_`、`is_` など）。<br>非公開（内部用）の関数は先頭に `_` を1つ付与する。                      | `calculate_total()`<br>`is_valid()`<br>`_internal_process()`                               |
| **引数名**<br>（関数メソッド）         | **すべて小文字**<br>（スネークケース）               | 通常の変数ルールに準拠する。<br>インスタンスメソッドの第1引数は **`self`** とする。<br>クラスメソッドの第1引数は **`cls`** と定義する。      | `def greet(self, user_id):`<br>`def create(cls, data):`<br>`def check(id_):`（予約語回避） |
| **メソッド名**                         | **すべて小文字**<br>（スネークケース）               | 関数と同様のルールを適用（動詞から開始）。<br>外部からのアクセスを想定しない内部用は、先頭に `_` を1つ付与する。                             | `self.deposit()`<br>`self._log_transaction()`                                              |
| **インスタンス変数名**                 | **すべて小文字**<br>（スネークケース）               | データや状態を示すため、原則として**名詞または形容詞**で命名する。<br>内部専用とする場合は、先頭に `_` を1つ付与する。                       | `self.owner_name`<br>`self.is_active`<br>`self._balance`                                   |
| **変数名**                             | **すべて小文字**<br>（スネークケース）               | 一文字の変数名（ `l`, `O`, `I` ）は視認性が著しく低いため**使用禁止**とする。<br>コレクション（リスト等）は複数形（末尾に `s` ）を推奨する。 | `total_price`<br>`user_name`<br>`for i in range(5):`（ループ用）                           |
| **定数名**                             | **すべて大文字**<br>（スクリーミングスネークケース） | Python言語仕様上の定数強制力はないため、大文字表記で定数であることを明示する。<br>より厳格に制御する場合は `typing.Final` を活用する。       | `TAX_RATE`<br>`MAX_LOGIN_ATTEMPTS`<br>`MAX_USERS: Final = 100`                             |

## 2. 特殊なアンダースコア（ `_` ）の規約

Pythonにおけるアンダースコアの数と配置には、以下のシステム的な意味および暗黙の了解が存在する。

* **`_single_leading_underscore` （先頭に1つのアンダースコア）**
  * 内部使用（プライベート）であることを明示する。
  * `from module import *` を実行した際、インポート対象から除外される。
* **`single_trailing_underscore_` （末尾に1つのアンダースコア）**
  * Pythonの予約語（キーワード）や組み込み関数との名称衝突を回避するために用いる（例： `id_`, `class_` ）。
* **`__double_leading_underscore` （先頭に2つのアンダースコア）**
  * クラス内属性に適用した場合、名前修飾（ネームマングリング）が作動する。
  * 外部やサブクラス（子クラス）からの意図しない上書きやアクセスを防ぐ目的で使用する。
* **`__double_leading_and_trailing_underscore__` （両端に2つのアンダースコア）**
  * Pythonがシステム側で定義している特殊メソッド（マジックメソッド / ダンダーメソッド）に適用される。
  * 開発者が独自にこの形式の名称を定義してはならない（例： `__init__`, `__str__` ）。
